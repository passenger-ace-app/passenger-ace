## 14차: 정차 화면 움직임 (2026-11-12, Pleos_Connect 에뮬레이터, 창 없이)

- 화면 종류가 바뀔 때 오른쪽 글 묶음이 0.22초 동안 투명도 0→1, 아래 12dp→0으로 들어온다. 표지 그림은 움직이지 않는다.
- 물어보기 "듣고 있어요" 화면에서 마이크 뒤 원이 1.2초마다 크기 1→1.25, 투명도 0.35→0으로 숨 쉰다.
- 발견: 차 신호(배터리 등)가 2~3초마다 들어와 화면을 다시 그린다. 화면이 바뀐 뒤 0.04초, 0.14초에 다시 그려 등장 움직임이 지워졌다(로그로 확인).
  - 고침: 화면 종류가 바뀐 시각을 기억해, 다시 그려도 남은 움직임과 원의 박자를 이어 간다.
  - 확인: 애니메이션 속도를 10배로 늦춰 연속 캡처, 글 묶음이 7장에 걸쳐 서서히 나타남. 원은 녹화에서 커졌다 사라지는 것을 확인.
- 시스템 애니메이션이 꺼져 있으면 움직이지 않는다. 주행 중(D)에는 앱 화면이 없어 움직임도 없다.
- release APK를 새로 깔아 첫 화면 → 알림 허용 → 재생 → 물어보기까지 확인, crash 없음. 단위 시험 141개 통과.

| 화면 2의 이야기 목록 버튼 글자가 가운데가 아니라 왼쪽 테두리에 붙었다(기대 1143, 실제 1027) | 화면 그림. 측정은 통과하고 있었다 | 글자 뷰를 내용 크기로. `screen2Again`이 글자가 그려진 자리를 잰다 |
| 30초 판단을 벽시계로 쟀다. 차 시계가 맞춰지면 판단이 틀어질 수 있다 | 시험 시계가 앱에 안 먹어서 드러남 | `SystemClock.elapsedRealtime` |
| 이야기 목록을 `assets.list`로 찾아 Robolectric에서 서비스가 시작하다 죽었다. 이 환경의 폴더 목록 형식이 달라서다. 실제 기기에서도 죽는지는 모른다 | 서비스 시작 예외 | `index.json`을 직접 열어 본다. 기기에서도 그대로 동작하는 방식이다 |

중간에 제가 쓴 가운데 정렬 시험이 뷰 상자만 재서 버그가 있는데도 통과했다. 글자 자리를 재도록 고치고, 앱을 고치기 전에 실패하는 것을 확인했다.

## 여전히 기기로만 볼 수 있는 것

| 항목 | 왜 기기가 필요한가 |
|---|---|
| 실제 소리, mp3 재생, 끝남 신호 | MediaPlayer가 대역이다. 파일을 해독하지 않는다 |
| 줄 사이 끊김, 이어 갈 때의 시간차 | 소리 길이를 8초로 고정했다 |
| 다른 앱이 소리를 가져갈 때 시스템이 실제로 CAN_DUCK과 복귀를 보내는지 | 시험이 신호를 직접 넣었다 |
| `navsim` 전체. 뒤에서 소리 권한을 얻는지, 브로드캐스트가 닿는지 | 한 번도 실행하지 않았다 |
| 실제 미디어 키 전달 | 시험이 세션 처리기를 직접 불렀다 |
| `dumpsys media_session`, 시스템 미디어 줄 표시 | 세션에 넣은 값까지만 봤다. 값은 시험용 기록 대역으로 읽었다 |
| 팝업이 실제로 뜨고 6초 뒤 사라지는지, `dumpsys notification` | 게시 내용까지만 봤다 |
| 포그라운드 서비스 규칙, 알림 권한 동작 | 시스템이 막는지는 대역이 판단하지 않는다 |
| 앱 강제 종료 뒤 저장 유지 | 같은 프로세스에서 서비스만 다시 만들었다 |
| adb 브로드캐스트가 수신기에 닿는지 | Robolectric이 필터 없는 수신기에 전달하지 않아 실제 수신기를 직접 불렀다 |
| 기어 D에서 앱이 실제로 뒤로 가는지 | 화면을 다시 그리지 않는 것까지만 봤다 |
| `onLoadChildren`, 차의 미디어 화면 연결 | 실행하지 않았다 |
| API 37 이미지, target 34 앱 동작 | SDK 34 환경에서만 돌렸다 |
| 실제 창에서의 표시줄과 겹침 | 뷰를 직접 재서 그렸다. 1008은 어림값이다 |

그림에서 본 작은 차이: 굵기 500에서 라틴 글자만 굵어져 "기어 P"의 P가 "기어"보다 진하다. 고치지 않았다.

Robolectric은 처음 돌릴 때 인터넷에서 안드로이드 이미지를 내려받는다. `android.useAndroidX=true`는 시험 의존성 때문에 넣었고 앱에는 androidx가 없다.

## 기기 시험을 못 돌린 이유

이 PC의 BIOS에서 가상화(AMD SVM)가 꺼져 있다. 연결된 실기기도 없다. 그래서 위의 Robolectric 시험을 대신 넣었다.

실제로 본 출력.

```
$ emulator -avd Medium_Phone_API_37.0 -no-window -no-audio -no-boot-anim
ERROR        | x86_64 emulation currently requires hardware acceleration!
CPU acceleration status: Android Emulator hypervisor driver is not installed on this machine

$ emulator -accel-check
Android Emulator hypervisor driver is not installed on this machine

Win32_Processor
VirtualizationFirmwareEnabled           : False
VMMonitorModeExtensions                 : True
SecondLevelAddressTranslationExtensions : True

Win32_ComputerSystem HypervisorPresent  : False
adb devices -l                          : 목록 없음
```

CPU는 가상화를 지원하지만(`VMMonitorModeExtensions`) 펌웨어에서 꺼져 있다.

소프트웨어 모드도 두 번 시도했고 둘 다 시작 중에 죽었다.

```
$ emulator ... -accel off -gpu swiftshader_indirect
WARNING      | x86_64 emulation may not work without hardware acceleration!
종료 코드 139

$ emulator ... -accel off -gpu guest
Segmentation fault, 종료 코드 139
```

AVD의 `userdata-qemu.img`가 10MB뿐이라 이 AVD는 전에도 끝까지 부팅된 적이 없어 보인다.

### 풀려면 (사람이 해야 한다)

1. PC를 다시 켜고 BIOS에 들어가 SVM Mode를 켠다.
2. 윈도우에서 "Windows 하이퍼바이저 플랫폼"을 켜거나, SDK Manager에서 Android Emulator hypervisor driver를 설치한다. 둘 다 관리자 권한이 필요하다.
3. 아래 명령을 차례로 돌린다.

실제 안드로이드 폰을 USB로 연결해도 되지만 화면 크기 시험은 다시 맞춰야 한다.

## 단위 시험

실제 출력.

```
AlertPolicyTest 11
NarratorTest 25
SampleRouteTest 2
ScenarioTest 4
ScreensTest 11
StoryServiceTest 17
합계 70, 실패 0
BUILD SUCCESSFUL
```

아래 표는 안드로이드 없이 도는 순수 로직 시험 50개다. 처음 50개는 하나도 깨지지 않았다.

| 규칙 | 잡는 시험 |
|---|---|
| 1 깜빡이, 기어로 안 멈춤 | `turnSignalGearDoNotStopStory` |
| 2 문장 처음부터, 30초 기준 | `transientLossResumesSameLineSilently`(정확히 30초), `longStopSaysResumeThenSameLine`(30.001초), `turnOffThenOnSaysResume` |
| 3 끈 뒤 자동 시작 안 함, 영구 손실 | `afterPauseFocusGainDoesNothing`, `pauseDuringNavStaysOff`, `offMeansNoAlert`, `permanentLossDoesNotResume` |
| 4 미리 알림 | `alertInterruptsAndResumesSilently`, `navDuringAlertCutsIt`, `cutAlertNeverComesBack`, `neverAtOrInside1000m`, `repeatOnlyOnceBetween1500And1000`, `sameSideSignalStopsRepeatEvenIfTurnedOffAgain`, `otherSideSignalDoesNotStopRepeat` |
| 5 팝업 문구 | `alertInterruptsAndResumesSilently`(Popup 출력까지) |
| 6 상태 글자 | `statusOnlyWhenItChanges`, `requestFocusIsLastSoStatusIsNotOverwritten` |
| 7 다음 키 | `nextGoesToOtherUnheardStory`, `nextWhileNavSpeaksWaitsForFocus`, `nextWhileOffStartsStory` |
| 8 한 편 끝나면 멈춤 | `storyEndStopsAndPicksNextUnheard`, `allHeardStartsFromFirstAgain` |
| 9 말수 적게 | `talkLessNeverSpeaks`, `talkLessStillAlerts` |

`ScenarioTest`는 표본 주행 203초 전체를 가짜 시계로 돌린다. 줄 길이 8초, 말 6초, 내비 4초로 둔 값이다. 실제 소리와 소리 권한을 쓰지 않는다. 기기 시험을 대신하지 않는다.

- 같은 쪽 깜빡이를 켠 경우: 내비 5번, 알림 1번, 끊긴 6번 모두 같은 줄에서 이어 감.
- 깜빡이가 없는 경우: 알림 2번(94초, 135초).
- 알림 중 내비 끼어들기: 알림 1번으로 끝, 다시 안 함.
- 20초에 끈 경우: 그 뒤로 줄도 알림도 없음.

## APK 점검

실제 출력.

```
--app
uses-permission: android.permission.FOREGROUND_SERVICE
uses-permission: android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK
uses-permission: android.permission.POST_NOTIFICATIONS
sdkVersion:'29'  targetSdkVersion:'34'
uses-feature-not-required: android.hardware.type.automotive
--navsim
권한 없음. sdkVersion:'29'  targetSdkVersion:'34'

app-debug.apk 소리 파일 88개, 압축된 것 0
navsim-debug.apk 소리 파일 5개, 압축된 것 0
```

INTERNET, SYSTEM_ALERT_WINDOW가 없다. 소리 파일이 압축되지 않아 `openFd`로 열 수 있다.

자산: 미다스 왕의 손 26줄 2.6분, 세 가지 질문 31줄 3.9분, 햄릿 21줄 2.3분. 세 편 모두 들어갔다.

린트(`:app:lintDebug`): 오류 2개가 남았다. 둘 다 안드로이드 오토의 음성 검색(`MEDIA_PLAY_FROM_SEARCH`, `onPlayFromSearch`) 요구다. 음성은 이번 범위 밖이라 그대로 뒀다. minSdk 위반(NewApi)은 없다. 경고 11개는 target 버전, 앱 아이콘 없음, 내보낸 서비스(차 미디어 화면이 붙으려면 필요) 같은 것이다.

## 기기 시험 명령

아직 한 번도 돌리지 않은 명령이다. 처음 돌릴 때 고칠 곳이 나올 수 있다. 아래에서 `ADB`는 SDK의 adb다.

```bash
# 준비
emulator -avd Medium_Phone_API_37.0 -no-window -no-audio -no-boot-anim
ADB install -r -t app/build/outputs/apk/debug/app-debug.apk
ADB install -r -t navsim/build/outputs/apk/debug/navsim-debug.apk
ADB shell wm size 1920x1080
ADB shell wm density 160
ADB shell pm grant app.passengerace android.permission.POST_NOTIFICATIONS
ADB shell am start -n app.passengerace/.MainActivity

# 로그 보기 (창 하나를 띄워 둔다)
ADB logcat -c
ADB logcat -s ACE

# 자주 쓰는 신호
nav()  { ADB shell am broadcast -n app.passengerace.navsim/.NavReceiver -f 0x20 --ei n ${1:-0}; }
sig()  { ADB shell am broadcast -n app.passengerace/.SampleSignalsReceiver -f 0x20 "$@"; }
gear() { sig -a app.passengerace.GEAR --es gear $1; }
turn() { sig -a app.passengerace.TURN --es turn $1; }
route(){ sig -a app.passengerace.ROUTE; }

# 버튼 자리 찾기
ADB shell uiautomator dump /sdcard/ui.xml && ADB shell cat /sdcard/ui.xml
ADB shell input tap <x> <y>
```

| 시험 | 조작 | 로그에서 볼 것 |
|---|---|---|
| a | 첫 화면 버튼을 탭 | `CLIP start` 뒤 `LINE midas 0`, `LINE midas 1` 차례 |
| b | `nav 0` | `FOCUS -3`, `STOP`, `STATUS midas WAITING`, 안내 끝나고 `FOCUS 1`, 같은 줄 `LINE midas N`. 멈춘 동안 `ADB shell dumpsys media_session`에 "안내 뒤 이어 가요" |
| c | `ADB shell input keyevent KEYCODE_MEDIA_PLAY_PAUSE`, `nav 1`, 다시 키 | 끈 뒤 `NAV end`가 나와도 `LINE` 없음. 다시 키를 누르면 `CLIP resume` 뒤 끊긴 줄 |
| d | `ADB shell input keyevent KEYCODE_MEDIA_NEXT` 두 번 | `LINE three-questions 0`, `LINE hamlet 0`. 세 편이 다 들어 있어 시험용 표시가 필요 없다 |
| e-1 | `route`, 분기 2400m(94초) 뒤 1500m(135초) 전에 `turn RIGHT` | `ROUTE nav` 5번, `ALERT at`, `POPUP` 1번, 끊긴 줄마다 같은 줄 다시 시작. `ADB shell dumpsys notification`에서 "맨 오른쪽 차선으로" |
| e-2 | `turn NONE`, `route`, 깜빡이 없이 | `ALERT at` 2번 |
| f | `turn NONE`, `route`, `ALERT at`이 보이면 바로 `nav 0` | `ALERT cut`, 그 뒤 `ALERT at` 없음 |
| g | `ADB shell am force-stop app.passengerace`, `am start`, 듣기 | `SERVICE start story=... line=N`이 끊긴 자리. `CLIP resume` 뒤 같은 줄 |

화면 캡처: `ADB exec-out screencap -p > docs/화면/화면-1.png`. 지금 `docs/화면/`의 5장은 Robolectric 그림이다. 기기 캡처로 덮어쓴다. 앱은 시스템 표시줄을 숨기지 않으므로 세로로 약 70dp 작게 나온다. 높이 1008 측정은 통과했지만 실제 창에서 눈으로 확인해야 한다.

기어 D 시험: `gear D`로 앱이 뒤로 가는지, `gear P` 뒤 앱을 다시 열어 본다.

끝나면 되돌린다.

```bash
ADB shell wm size reset
ADB shell wm density reset
ADB emu kill
```

## 아직 모르는 것

- `-no-audio`로 띄운 에뮬레이터에서 MediaPlayer가 끝까지 재생하고 끝남 신호를 주는지.
- `navsim`이 뒤에서 소리 권한을 얻는지. Android 15부터 앞 화면이 아닌 앱의 소리 권한 요청을 막는데, target 35 이상에만 걸리는 것으로 알고 있다. 기기에서 확인해야 한다.
